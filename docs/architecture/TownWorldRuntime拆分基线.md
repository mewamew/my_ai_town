可执行基线位于
`tools/guards/world_runtime_architecture_baseline.json`，由
`tools/guards/world_runtime_architecture_check.py` 检查。它已经接入
`tools/guards/run_guards.sh`。

## 2. 这次治理要解决什么

`TownWorldRuntime` 已经引用活动、工作、职业、货物、生产、社会事务、身体状态和生命周期等
专用模块，但中心文件仍然持有大量原始状态，并承担启动、推进、存档恢复、决策、行动、对话、
投影和跨业务协调。周边模块又通过 `world._xxx` 回读或修改中心私有成员，导致文件虽然分开了，
状态所有权和依赖边界仍然集中在总控。

治理完成后，总控只保留以下职责：

1. 组装有明确类型的业务模块。
2. 保留旧公共入口并转发，确保调用方不需要同时迁移。
3. 在既有时点递增世界版本、分配 ID、写日志和发送公共信号。
4. 协调真正跨业务、无法归入单一模块的短事务。

它不再直接保存各业务的原始字典，也不再包含大段具体规则。

## 3. 状态归属迁移顺序

| 阶段 | 当前状态 | 目标拥有者 | 本阶段不允许改变 |
|---|---|---|---|
| E1 旅行者关系 | `_traveler_relations` | `TownTravelerRelationshipState` | 熟悉度、亲密度、攻击扣减、幂等规则、存档字段 |
| E2 活动缓存 | `_activity_reachability_cache`、`_activity_prepared_action_cache`、`_activity_reachability_cache_minute` | `TownActivityReachabilityCache` | 缓存键、分钟失效、恢复清空、行动准备结果 |
| E3 动态物件 | `_dynamic_props`、`_indoor_layout_overrides` | `TownDynamicPropRuntime` | 身份校验、排序、地点归属、Agent 投影、布局存档字段和恢复清空策略 |
| E4 表现刷新队列 | 三个居民刷新/地点信号队列字段、两个感知延期字段 | `TownWorldFrameBudgetRuntime` | 去重、预算、最大延期、地点合并和信号顺序 |

E1～E4 是低风险试点。四项完成并复盘接口后，才进入私信、公告、社会、地点、职业、生产、
身体和冲突等业务域；居民主字典、决策队列、行动执行、存档恢复和时间推进放在更后面的阶段。

## 4. 每个迁移目标的固定步骤

1. 列出目标状态的所有读写点、公开入口、信号、版本号变化、存档字段和生产调用方。
2. 先用现有全链路测试记录正常、错误、空值、边界、重复调用和恢复行为；覆盖不足时补特征测试。
3. 新模块先实现与旧逻辑一致的状态操作，并有不依赖完整世界对象的直接测试。
4. 一次性迁移状态所有权，旧总控不保留第二份可写状态。
5. 旧公共入口继续存在并转发；返回结构、错误码和引用语义保持不变。
6. 世界版本、ID、日志和信号仍在原来的时点发生。
7. 逐个去掉调用方对原始字典和 `world._xxx` 的访问。
8. 接入模块快照和恢复，但保持外层存档字段与过滤规则不变。
9. 收缩架构基线；基线脚本拒绝用更高数字覆盖旧基线。
10. 完成下面的无窗口验证后，才能开始下一个目标。

## 5. 每个目标的验证要求

每完成 E1、E2、E3 或 E4，至少执行：

1. `tools/guards/run_guards.sh`，确认架构指标和既有防复发检查全部通过。
2. Godot 无窗口导入，确认没有脚本解析、资源加载或引擎错误。
3. 目标模块直接测试和对应领域全链路测试。
4. 完整 Agent 离线套件，逐个观察通过标记、脚本错误、引擎错误和资源泄漏，不能只看退出码。
5. 测试后检查工作区，确认源码目录没有意外生成或改写文件。
6. 提交后在只包含该提交的干净临时工作区再次验证，再考虑推送。

## 6. 停止条件

出现以下任一情况，当前迁移立即停止，不继续叠加下一项目标：

- 公开方法、默认参数、返回字段或错误码无法保持。
- 世界版本递增次数、ID 序列、信号参数或顺序发生无法解释的变化。
- 新旧存档不能按原有规则恢复。
- 新模块仍需接收完整 `TownWorldRuntime` 并访问大量私有成员。
- 为通过检查需要增加私有访问、调高架构基线、扩大白名单或降低测试断言。
- Agent 套件出现缺少通过标记、脚本错误、引擎错误或资源泄漏。
- 测试后源码目录出现未解释的变化。

## 7. E0 完成判定

E0 不以“已经拆出文件”为完成标准，而以拆分是否可安全开始为标准：

- 架构规模和私有访问已经形成只能收缩的可执行基线。
- 无窗口测试能够准确区分功能失败与测试进程清理问题。
- 当前提交的 Agent 行为基线可以完整通过。
- E1～E4 的状态边界、保持项、领域测试和停止条件已经明确。

后续每完成一个状态迁移，都必须同步降低对应指标；不能只移动代码位置。
