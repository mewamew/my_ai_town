# 玩法插件化方案（scenarios 架构 · 施工总纲）

> **文档性质**：提案 + 施工图。目标是把"狼人杀式玩法"从世界内核中拔出，
> 建立可插拔的剧本包（Scenario Pack）体系，让后续任何类型的小镇玩法
> （推理局 / 选举局 / 纯生活模拟裸奔局）都能以"新增一个目录"的方式接入。
> 锚点行号以 wolf-migrate 分支 `50973db`（2026-08-26）为准，施工时以实际代码复核。
> 关联文档：`PROJECT_GUIDE.md` §5、`docs/architecture/TownWorldRuntime拆分基线.md`、
> `docs/学习笔记/加新动作全链路检查清单_新架构版.md`

---

## 一、问题定义与目标

**现状一句话**：项目是"静态内容已高度数据化 + 玩法逻辑硬编码于内核"的典型格局。
活动/日程/职业/地图走 source JSON → 烘焙管线，加内容零代码；但狼人杀作为第一个
非官方玩法，是通过在世界内核里直接调用约 30 个区块、230+ 处引用焊进去的。

**历史教训**：猫鼠 → 狼人杀已经交过两次"全链路学费"（旧巨石时代 10 关清单，
新架构后 8 步清单）。不做插件化，第三个玩法第三次交学费。

**目标**：
1. 世界内核不知道任何具体玩法的存在（依赖倒置）；
2. 一个玩法 = 一个自包含目录，换剧本不改内核；
3. 已被实战验证的机制（双通道动作、强制唤醒快速通道、公告调度、目击者派发）
   成为所有剧本共享的框架原语；
4. 每阶段迁移保持测试全绿、守卫通过、行为不退化。

**明确不做**：
- 不做第三方任意 GDScript 的沙箱加载（Godot 无法安全沙箱，成本收益倒挂）；
- 不重写 234 个 world/runtime 模块——只"开缝"，不动领域拆分成果；
- 一期不做多剧本并存的单局混装（单局绑定单剧本）；
- 一期不改 UI 层结构（现有日志面板/公告栏就是玩法的全部表现出口，这是本类
  游戏对插件化最大的天然优势）。

## 二、核心原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | 依赖倒置 | 内核广播生命周期事件，剧本订阅；内核永不 import `scenarios/`，由剧本向内核注册 |
| P2 | 声明优先 | 能写进 manifest/rules.json 的不写代码；常量、文案、卡司、策略开关全部数据化 |
| P3 | 类型化语义 | 跨模块传递的死亡原因、身份、阵营一律枚举/结构体，禁止中文子串匹配 |
| P4 | 行为保持 | 每步迁移结束跑对应套件 + 架构守卫；注册表防漂移测试同步演进 |
| P5 | 内容分级 | 三档 MOD：文案包(md) < 数据包(json) < 行为包(gd handlers)；低档永远先于高档考虑 |
| P6 | 单一激活声明 | 剧本自带 `activate_when`，取代散落各处的 feature_active 探测 |

## 三、剧本包规范

### 3.1 目录布局

```
game/scenarios/
└── werewolf/                     ← 第一个剧本：现狼人杀整体迁入
    ├── manifest.json             ← 身份/版本/兼容性/激活条件/策略覆盖
    ├── rules.json                ← 全部规则常量与文案模板
    ├── cast.json                 ← 阵营分配（固定卡司 或 随机配比）
    ├── prompts/
    │   ├── stances/police.md     ← 身份立场段（取代 PromptCompiler 内嵌文案）
    │   ├── stances/undercover.md
    │   └── roles/resident_bai_zhi_01.md …  ← 随包携带的具名角色规则
    │                               （迁自 game/prompts/roles/）
    └── handlers/                 ← 行为脚本（GameModeHost 实现者）
        ├── werewolf.gd           ← 原 TownWerewolfRuntime
        ├── role_skills.gd        ← 原 TownRoleSkillRuntime
        └── undercover_deadline.gd← 原 TownUndercoverDeadlineRuntime
```

### 3.2 manifest.json schema（v1）

```jsonc
{
  "schemaVersion": 1,
  "id": "werewolf",
  "name": "卧底疑云（狼人杀）",
  "version": "1.0.0",              // 写入存档 plugin_states.<id>.version，供恢复校验
  "engineMin": "0.1.0-beta.6",      // 最低内核版本
  "activateWhen": {                 // 取代两处重复的 feature_active 自动探测
    "residentFactionPresent": "undercover"
    // 备选形式: {"always": true} | {"openingFlag": "..."} | {"minResidents": n}
  },
  "overrides": {                    // 策略覆盖：剧本改引擎默认行为的唯一合法通道
    "residentReplacement": false,   // 死者不补位（经典狼人杀约束）
    "witnessStrictness": "night_only",
    "assassinateDaytimeBlocked": true
  },
  "saveDomain": "werewolfState"     // 存档命名空间键名（见 §8）
}
```

### 3.4 cast.json —— 卡司与随机分配

一期沿用"职业即角色"约定（警察身份=警察职业），把"谁担任"从内核常量改为剧本数据：

```jsonc
{
  "schemaVersion": 1,
  "roles": {
    "undercover": { "mode": "fixed",
                    "residents": ["resident_xie_mian_01","resident_qiao_yiming_01","resident_hanako_01"] },
    "police":     { "mode": "fixed", "residents": ["resident_wen_xu_01"] },
    "doctor":     { "mode": "byOccupation", "occupation": "医生" },
    "scholar":    { "mode": "byOccupation", "occupation": "图书管理员" }
  }
}
```

二期再放开 `"mode": "randomCount"`（从局内居民抽 N 名卧底），配合开局 OC 分析
（AgentSoulProfile）生成身份倾向。**randomCount 是通用性的试金石**，但不必一期做。

### 3.5 提示词加载时机改造

现状：静态层进程启动读入、改 md 必须重启游戏（AGENT_HANDOFF 血泪教训 #6）。
改造：剧本包内的 prompts 于**开档/读档时装载并缓存到会话级**。换剧本 = 开新档即生效，
开发迭代也免重启。实现落点：AgentPromptCompiler 的静态层缓存改由 ScenarioRegistry 提供。

## 四、宿主接口 GameModeHost（内核开缝清单）

原则：每个挂点都能在 §6 清单里找到它要替代的现状锚点。内核提供 `GameModeHost`
（RefRegister + EventBus 形态），剧本 handlers 在 `on_world_start` 里完成全部注册。

| 挂点 | 签名要点 | 替代现状（锚点见 §6） |
|---|---|---|
| on_world_start / restore | 注入 world 门面（窄接口：查居民/发公告/投递事件） | TWR:869-872 初始化; RestoreCommitRuntime:123-127 回填 |
| on_minute(minute, phase) | phase 排序元数据显式声明；保序约束："技能结算必须先于天亮死讯 flush" 从注释约定变为注册项 priority | AdvanceRuntime:145-148 写死调用链 |
| on_death(resident_id, cause) | cause 为类型化 DeathCause；返回公告策略（立即/压到天亮批量） | DeathConfirmationRuntime 夜间延迟逻辑 + EXILE_REASON 字符串比对(:145,:168) |
| register_attachment(name, validator, submitter) | 决策附件通道（如 exile_vote / night_skill） | SubmissionRuntime:182-193 if链; Snapshot._validate_exile_vote/_validate_night_skill 白名单硬编码 |
| register_instant_action(type, schema, handler) | 即时动作通道（投票放逐/使用技能/暗杀/制服/追踪/查案） | Registry ALL_TYPES+T4; Validation 字段白名单+形状分支; SubmissionRuntime:327-465 分流 if 链 |
| decorate_wake_snapshot(ctx, packet) | 追加快照扩展区（exile_vote 候选/night_skill 列表/额度耗尽旗标）+ 冲突张力特权选项 | WakePreparationRuntime:475-496; WakeContext:199-213; PacketProjection:86-89; WorldQueryRuntime:65-70 + TWR:2624-2805 选项装饰 |
| prompt_contributions() | 身份立场文本(按 faction)、动作提交 JSON 模板、约束构造器 | PromptCompiler:85-89 stance 内嵌、:1686-1708 模板、:2207/:2230 约束 |
| save_domain() -> {snapshot(), restore(d)} | 存档命名空间域 | SaveCodec:53 顶层白名单 + :392 校验; SaveCommandRuntime:63; SaveSnapshotProjection:83-84 |
| policy_override(key) -> value | 引擎默认策略的读取点统一走这里，缺省回退内置值 | GameFlowHost 无条件 return 禁补位等（§6-J 类） |

**内核提供给剧本的服务（原语层）**——这些是已验证机制的公共化，第二剧本可直接复用：

1. 合规三件套：决策附件通道 / 即时动作通道 / Gateway 强制唤醒快速通道
   （Gateway:2967-2978 投票必投），对应 LLM 遵守度不稳的三级递进对策；
2. 公告调度服务：延迟到指定时刻批量公布（夜间死讯 08:00 flush 的通用化）；
3. 目击者事件派发服务（TWR:3711/3756 通用化）；
4. 事件队列事实投递（目睹/被救/查验结果等 EVENT_TYPES 注册制）。

## 五、语义地基专项（必须最先施工）

以下三处"字符串即契约"是数据外提后必然炸雷的点，属于 Phase 0：

1. **死亡原因类型化**。现状三处跨模块中文匹配：
   - DeathConfirmationRuntime defer_night_death_announcement 用 `reason.contains("暗杀")`;
   - TWR `_death_announcement_text`:2526 用 `reason.contains("制服")`;
   - EXILE_REASON 精确文案比对（同文件 :145/:168）。
   改为 `DeathCause` 枚举（ASSASSINATION/SUBDUE/EXILE/NATURAL…）+ 结构化载荷，
   文案由剧本 texts 渲染。
2. **职业/身份判定去字符串化**。"谁是警察"目前靠 `job == "警察"`
   （TWR `_resident_is_police`:2493、PromptCompiler:87 等多处）；is_undercover 靠合同
   身份字段。统一为开局由 cast.json 生成的 `faction/role` 组件挂到居民状态。
3. **feature_active 双份实现合一**（WerewolfRuntime:207-212 与 RoleSkillRuntime:90-95
   重复遍历探测）→ 收敛为 manifest.activateWhen 单点判定，结果经 host 下发。

## 七、施工路线（R = restart-fork 重放 + 插件化一次成型）

> 关键决策：既然确定从官方最新版重建（另见《迁移手册》新增章节），**集成点反正要在

## 八、存档与兼容策略

1. `state.pluginStates` 成为编解码器已知容器（允许任意字符串键 + 版本字段），
   剧本状态挂在 `pluginStates.werewolf`。
2. 恢复规则：容器键缺失 = 剧本未启用，跳过不报错；剧本 version 与 manifest 不兼容
   时走"拒载提示"而非静默降级（沿用上游坏档页交互惯例）。
3. 旧档一次性适配：读到旧顶层 `werewolfState` 键时迁入命名空间（一个迁移函数 + 
   存档只读检查器用例），沿用上游 #146 建立的迁移账本模式登记。
4. 注意：本地领先提交里的 finish_reason 类型防御、refresh 看门狗两个修复位于
   Gateway/Provider（重叠文件），重放前需先核对 origin/main 是否已有等效修复，
   有则丢弃、无则重放。

## 十、风险登记

| 风险 | 缓解 |
|---|---|
| LLM 对新动作遵守度不稳导致玩法失效 | 合规三件套永远是剧本可选武器；投票那次的经验（附件→动作双通道）已成方法论 |
| 重放期两个行为（旧焊接 vs v3 插件态）漂移而不自知 | R6 真实跑局对比；diag 测试先行平移（R1）作护栏 |
| 上游继续演进再拉开差距 | 场景目录整包 rebase 成本≈0；内核侧只剩挂点骨架，面积小且稳定 |
| PolicyOverride 被滥用为万能后门 | overrides 键白名单收口在引擎代码里逐个 eval，剧本不能注入任意钩子 |
| license 未定影响远期第三方分发 | 第一方不受影响；开放 user://mods 前必须先解决授权（README 授权说明） |
