# 历史存档样本

仓库保存 beta1 至 beta6 各一份由对应发行写入器重建的完整磁盘样本，并补充 beta5 的活动生命周期和长路径边界样本。样本保留生产目录结构；Godot 日志和对象调试快照不进入仓库。

这些样本不是玩家原档。项目无法取得玩家原档，因此只根据 Git tag、发行提交、当时的字段和原写入器反推兼容行为。生成器只加入取样与场景钩子，正式数据仍由对应版本的写入器落盘。

完整来源、逐文件 SHA-256 和预期 beta6 结果见 `game/tests/fixtures/historical_saves/catalog.json`。

## 验证

```bash
python3 tools/persistence/verify_historical_save_fixtures.py
```

通过结果必须是：

```text
HISTORICAL_SAVE_FIXTURES_PASS fixtures=8 files=545
```

beta1 至 beta5 升级到 beta6，并验证 beta6 直接继续的业务闭环：

```bash
game/tests/run_historical_save_migration_matrix.sh
```

重新生成候选样本时，在干净工作区运行：

```bash
tools/persistence/generate_historical_save_fixtures.sh .tmp/historical-save-fixtures
```

生成器会核对发行提交和原测试哈希，执行六轮 26 项保存恢复检查，再生成两份边界样本并调用同一验证器。校验器会更新运行时产生的 session 和自定义居民 ID，再核对 manifest 引用、逐文件 SHA-256、活动状态、结算效果、U+001F 原始字节和最长路径。

长路径样本在 macOS 上生成，用于稳定复现超过传统 Windows `MAX_PATH` 的目录结构；`formal-validation` 的 Windows 任务会实际升级 beta5 长路径样本，并验证继续、再保存、重开、中断事务锁、重读、封口和递归清理。六版本矩阵继续在 Linux 验证全部发行版。
