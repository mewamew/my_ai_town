# 审讯会实机测试指南（diag_assembly_live）

> 2026-08-29 新增。解决一个痛点：**审讯会固定在第 2 天早上 08:00 触发**，
> 真机跑一次要等一整天的游戏时间；本测试台用"大步快进 + 真实 LLM"把整个
> 审讯会压缩到 **约 5 分钟真实时间**，并自动判定通过/失败。
> 首次实跑记录（0829）：汇报 14/14、警察审讯 4 人、12 票开票、0 报错，约 ¥1 额度。

---

## 一、快速开始

前置条件（一次性）：

1. 用正常方式启动过游戏并在设置里配好 LLM provider（模型服务）——
   测试台读取的是用户存档目录里的 provider 配置，没有配置会直接退出。
2. Godot 无头版路径：`F:\tools\godot\Godot_v4.7.1-stable_win64_console.exe`

运行命令（任选其一）：

```powershell
# 方式 A：直接跑，输出重定向到固定文件
F:\tools\godot\Godot_v4.7.1-stable_win64_console.exe --headless `
  --path F:\my_ai_town_upstream\game `
  --script res://tests/diag_assembly_live.gd `
  > F:\my_ai_town_upstream\logs\runs\diag_assembly_live.log 2>&1

# 方式 B：用启动脚本（自动按时间戳归档日志到 logs\runs\）
cd F:\my_ai_town_upstream
.\run-game-log.ps1 --headless --script res://tests/diag_assembly_live.gd
```

结束标志：最后一行 `ASSEMBLY_LIVE_PASS checks=N`（通过，退出码 0）或
`ASSEMBLY_LIVE_FAIL: ...`（失败，退出码 1）；provider 未配置时打印
`ASSEMBLY_LIVE_UNAVAILABLE` 退出码 2。

## 三、参数（环境变量）

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `AI_TOWN_ASSEMBLY_LIVE_CAP` | 960 | 冻结期（汇报+审讯+投票合计）的真实秒上限，超时判失败 |

就这一个参数。脚本内常量（改脚本才生效，一般不用动）：
`FFWD_STEP_MINUTES=120`（快进步长，游戏分钟/步）、`PUMP_INTERVAL_FROZEN_MSEC=400`
（冻结期决策泵间隔）、`REPORT/INTERROGATION/VOTE_PHASE_CAP_SEC`（单阶段上限
170/660/130 秒，略大于世界内建超时 120/600/90）。

设置示例（PowerShell）：

```powershell
$env:AI_TOWN_ASSEMBLY_LIVE_CAP = "1200"; .\run-game-log.ps1 --headless --script res://tests/diag_assembly_live.gd
```

## 四、测试流程（脚本内部做了什么）

1. **编新存档**：`TownWorldDataBuilder.build_from_source` 重建世界数据 +
   `TownNewGameOpeningCompiler` 编译开局（15 名推荐居民），等价"自己开新档"，
   从第 1 天 08:00 开始。
2. **接真实模型**：读用户保存的 provider 配置 → `configure`（formal 模式，
   `allowFake=false`）→ 健康检查，失败立即退出（不产生消耗）。
3. **快进第 1 天（零 LLM 消耗）**：循环大步 `advance(120 游戏分钟)`，
   **期间不 pump 决策**——居民不会发请求。步进的终点始终精确落在下一个
   08:00（大会触发条件是 advance 结束时刻 `minute_of_day==480` 且
   `day_index>=1` 且当天未开过），第 2 天 08:00 落点那一步会同时完成
   天亮死亡公告 + 大会触发。约 12 步、几十秒。
4. **冻结期逐秒驱动**：进入汇报期后改为**每真实秒 `advance(1.0)`**——
   阶段超时按真实秒累计，与真实游戏同速（这样模型有真实时间回答）；
   每帧 `_advance_agent_preparation`，每 400ms `pump(1)` 派发决策；
   每 10 秒打印一次阶段状态。
5. **自动散场**：汇报期（收齐优先，≤120s 超时）→ 审讯期（警察"结束审讯"
   或 600s 超时）→ 投票期（收齐立即开票或 180s 超时）→ 散会解冻，输出报告。

## 五、输出怎么读

日志标签（`ASSEMBLY_LIVE_*`）：

| 标签 | 含义 |
|---|---|
| `START / OPENING / HEALTH_PASS / READY` | 初始化三步：参数、开局、provider 就绪 |
| `FIRED` | 快进完成、第 2 天 08:00 大会触发并冻结 |
| `PHASE: report/interrogation/vote` | 进入各阶段（含世界时间） |
| `STATE` | 每 10 秒的阶段状态：reports 已汇报数 / interrogated 已审数 / votes 已投票数 / errors 累计错误 |
| `DECISION` | 每个完成的模型决策：居民、ok、动作类型 |
| `DISMISSED` | 大会散会解冻 |
| `SUMMARY` | 汇总：reports / maxInterrogations / votes / fallbacks / whitelistRejects / actionTypeErrors / endReasonErrors |
| `PASS checks=N` / `FAIL: ...` | 最终判定（N 为断言数） |

世界侧 `[WEREWOLF]` 行（汇报/审讯/开票原文）和 `[AGENT]` 行（可选/选择了）
与真机完全同格式，可直接对照排查。

自动验收断言（失败即 `ASSEMBLY_LIVE_FAIL`）：

1. 第 2 天 08:00 大会触发并冻结；
2. 警察至少发起 1 次审讯（interrogationCount ≥ 1）；
3. 审讯期产生逐字稿记录；
4. 投票或汇报链路有产出；
5. 大会正常散会解冻（phase 回到 idle）；
6. 全程 **0 次** `不是合法动作类型`（契约登记回归）；
7. 全程 **0 次** `不是合法对话结束原因`（对话原因枚举回归）。

## 六、成本与时长

- 真实时长：约 **5 分钟**（快进 ~40 秒 + 汇报期 ~15 秒 + 审讯期 ~3 分钟 +
  投票期 ~45 秒）。
- LLM 请求：约 50~100 次（14 汇报 + 审讯对话十余轮 + 14 投票 + 少量重试），
  约 **¥1 额度**（tokenrhythm 计价）。快进阶段零消耗。
- 不触碰真实存档：新档槽未发布过修订，散场自动丢弃；Agent 存储目录自动删除。

## 七、改完什么代码要跑它、怎么分层回归

| 改动 | 跑什么 |
|---|---|
| 大会状态机/白名单/契约动作（无 LLM） | `diag_assembly_state_machine.gd`（147 checks，秒级，零成本） |
| 投票语义 | `diag_werewolf_vote.gd`（72 checks） |
| **大会相关任何改动后的最终验收** | **`diag_assembly_live.gd`（真实 LLM，~5 分钟）** |
| 限流/请求节奏 | `diag_live_session.gd`（另一个用途的实机台） |

分层原则：先跑确定性 diag 抓逻辑错，最后用实机台验证"prompt 教的格式 →
契约校验 → 白名单 → 世界受理 → 模型理解"全链路——**很多 bug 只在真实
LLM 环节暴露**（如实证过的"prompt 教的类型契约不认识"）。

## 八、常见失败排查

| 现象 | 原因与处理 |
|---|---|
| `ASSEMBLY_LIVE_UNAVAILABLE` | provider 未配置：先用正常方式启动游戏，在设置里配好模型服务 |
| `ASSEMBLY_LIVE_PROVIDER_FAIL` | provider 配置存在但 formal 模式加载失败：检查凭据 |
| `ASSEMBLY_LIVE_HEALTH_FAIL` | 网络/凭据无效，或模型服务不可用 |
| `ASSEMBLY_LIVE_NO_TRIGGER` | 快进没触发大会：确认世界里有卧底（`feature_active`，本 fork 卧底名单写死在 TownWorldRuntime）且天数 ≥1 |
| `ASSEMBLY_LIVE_PHASE_TIMEOUT` | 某阶段卡死超过上限：看日志里最后一个 `STATE` 与 `[WEREWOLF]` 行定位（大概率是新 bug，拿日志找代码） |
| `SCRIPT ERROR ... Warning treated as error` | 本项目把 GDScript 推断警告当错误：变量从 Variant 推断时需显式写类型注解 |
| 汇报数 < 14 但 PASS | 允许个别模型偶发失败（http/JSON），只要审讯/散会断言过就算通过；若经常发生查 provider 稳定性 |
