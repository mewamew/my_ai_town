# 第 5 层：记忆系统精讲（新架构版）

> 目标：理解居民记忆从"证据→整理→干预→老化→检索→提示词"的完整生命周期，
> 以及它对狼人杀（身份隐藏/线索积累/疑心演化）意味着什么。
>
> 对应文件（新架构）：`game/agent/memory/`（13 个子模块）总入口 `ResidentMemorySystem.gd`，
> 头像记忆独立域 `game/agent/avatar_memory/`（5 个模块）。
>
> **架构变化**：旧版是"证据队列+整理+检索"三件套；新版扩成 13 模块，新增形式记忆
> （`ResidentFormalMemoryBuilder`）、干预服务/存储分离、老化服务、重评估、条目级存储、
> 摘要投影、连续性守卫——每个关注点一个协作者。

---

## 1. 记忆系统全景（memory/ 13 模块）

| 模块 | 职责 |
|---|---|
| `ResidentMemorySystem.gd` | ★总入口（每人一个实例）：prepare_context / retrieve_context / accept_decision / 干预应用 / 老化调度 |
| `ResidentEvidenceQueue.gd` | 证据队列：动作结果/事件 → "证据"（写盘队列，防卡顿） |
| `ResidentMemoryEntryStore.gd` | 条目级存储（记忆条目的持久化） |
| `ResidentMemoryStore.gd` | 记忆状态存储（每人一份私有文件 `user://agent_runtime_memory/<居民>/`） |
| `MemoryOrganizer.gd` | ★整理器：必要时一次 LLM 调用整理记忆（prompt=`prompts/memory/10_memory_organizer.md`），
| | 产出重要经历/关系/当前想法/长期目标/短期目标；`validate_candidate` 校验 |
| `MemoryContinuityGuard.gd` | 连续性守卫：整理不改变已确证事件的连续性 |
| `ResidentMemoryAgingService.gd` | 老化：旧/低置信记忆淡出（`_apply_automatic_memory_aging`） |
| `ResidentMemoryInterventionService.gd` + `ResidentMemoryInterventionStore.gd` | 干预：外部 apply（suppress/amend），服务与存储分离 |
| `ResidentMemoryReappraiser.gd` | 重评估：被新证据反驳的记忆降级 |
| `ResidentMemoryEvidenceMatcher.gd` | 证据匹配：新证据与既有记忆的相似度 |
| `ResidentFormalMemoryBuilder.gd` | ★形式记忆：结构化经历/关系/目标投影（`FORMAL_RECALL_MAX_ITEMS=6`） |
| `ResidentMemorySummaryProjector.gd` | 摘要投影：给提示词做紧凑摘要 |

**关键常量**（`ResidentMemorySystem.gd`）：
- `MEMORY_STATE_VERSION=6`（旧 `LEGACY_MEMORY_STATE_VERSION=5`，含迁移）
- `DEFAULT_MEMORY_ROOT="user://agent_runtime_memory"`
- `ORGANIZATION_BATCH_SIZE=4`（攒 4 条证据才整一轮）
- `FORMAL_RECALL_MAX_ITEMS=6` / `DECISION_IMPORTANT_MEMORY_LIMIT=2400`
- `MAX_RESIDENT_STORAGE_SEGMENT_LENGTH=48` / `RESIDENT_STORAGE_KEY_LENGTH=24`（存储键安全）

## 2. 记忆全流程（一次决策前后的记忆工作）

```
1. prepare_context(wake_packet)      ResidentMemorySystem L130
   └─ retrieve_context(wake_packet)  L172：检索相关记忆 → memory_context 注入提示词
2. 【居民决策（LLM）】
3. accept_decision(decision, wake)   L184：决策被世界确认后
   ├─ 新动作结果 → 证据入队（ResidentEvidenceQueue）
   ├─ 必要时触发整理（攒满 ORGANIZATION_BATCH_SIZE → MemoryOrganizer.build_request
   │    → LLM 整理 → validate_candidate → accept_organization L256 落库）
   └─ 形式记忆刷新（ResidentFormalMemoryBuilder，供提示词结构化引用）
4. 干预/老化（后台或事件驱动）：
   ├─ apply_memory_intervention(request)  L390（外部改记忆：审讯/记忆手术场景）
   ├─ _apply_automatic_memory_aging      L436（老化淡出）
   └─ _rollback_subjective_memory        L530（确证冲突时回滚主观记忆）
```

**记忆是私有文件**：`user://agent_runtime_memory/<居民>/`，居民互相看不到；
公开资料（名字/职业/声望）走 `world/` 共享数据，不走记忆文件。

**对外只读接口**（`get_read_only_memory` L579 + 一系列 `_public_*` 投影）：
- `_public_formal_memories` / `_public_person_labels` / `_public_basis` / `_public_interventions` /
  `_memory_state_summaries` / `_memory_certainty_summaries`
- 输出前会做 `_looks_like_internal_person_id` 检查，防止内部 ID 泄漏给表现层/LLM

## 4. 对狼人杀改造的意义（最重要的一环）

1. **身份隐藏**：卧底的任务记忆只有自己知道——`soul/AgentSoulProfile`（开局 OC 分析）只注入
   "行为倾向"，不把"我是卧底"写进公共数据；是否暴露身份完全由记忆演化决定
2. **警察线索积累**：怀疑对象列表写在警察的记忆里（回忆/证据匹配），
   配合 `TownAgentWakeContextRuntime._police_intel_context`（L445）在唤醒时注入警察情报
3. **全部张力在"谁知道什么、谁不知道什么"**——证据队列只给本人，关系证据
   （`relationship/TownTravelerRelationshipRuntime`）才跨人可见（且只是亲密度，不是内容）
4. **干预 = 审讯/洗脑玩法入口**：`apply_memory_intervention` 已支持 suppress/amend，
   "警察盘问结果改写记忆""卧底被嫁祸后记忆被污染"都能挂这
5. **老化 = 阴谋自然淡化**：旧线索随时间淡出，狼人杀"过了三天还在翻旧账"的 AI 行为
   可以通过老化参数调节（证据置信度/时间衰减）
