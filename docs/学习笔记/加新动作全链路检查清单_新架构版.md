## 0. 先分清：三类动作，登记表不同

| 类别 | 特点 | 名单 |
|---|---|---|
| 普通推进类（13 类） | 走 `_prepare_action` → 写 `currentAction` → 推进循环 → default_doing | 去/用道具/做活动/调整营业/托人传话/发布公告/待着/搭话/答话/投票放逐/使用技能/追踪/查案 |
| 冲突即时类（5 类） | 经冲突桥即时结算，**不写 currentAction、不进推进循环** | 争执/攻击/回应冲突/介入冲突/离开冲突 |
| 被硬拒改道类 | `_prepare_action` 直接拒，改走 activity.perform | 做活动 |

> ⚠️ 关键语义：冲突 5 类 + 狼人杀 4 类（投票放逐/使用技能/追踪/查案）都是**即时结算**，不出现在 T5/T6/T7 是**有意且正确**的（`CONFLICT_TYPES` 注释原文）。给它们补推进入口只会引入不可达代码。

## 5️⃣ normalize / 剥离（LLM 抄选项字段的容错）

**文件**：`game/agent/conflict/AgentConflictContract.gd` L106-142 + `game/agent/conflict/AgentConflictIntent.gd`

- **剥离** L106-117：LLM 常把 prompt 选项行里的 `option_id`（如 `assassinate:卧底:目标`）当作 `cause_id` 一并提交 → **白名单拒绝前先 `action.erase("cause_id"/"option_id"/"attack_kind")`**（暗杀/攻击场景）
- **attack_kind 归一** L121-131 + AgentConflictIntent L35：别名（kill/murder/致命 → lethal；扑/咬/拳 → unarmed）归一到 `ATTACK_KIND_ALIASES` 合法值
- **cause_id 重绑** L139-142：对话分支把当前唯一权威选项 option_id 绑回 cause_id

**验证**：`tests/diag_assassinate_normalize.gd`（剥离验证）、`tests/diag_kill_alias.gd` / `diag_intent_kill.gd`（kill→lethal 归一）。

**👣 加动作第五步**：若新动作带攻击语义，检查 normalize 剥离/别名归一是否覆盖。
