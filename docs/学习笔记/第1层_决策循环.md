# 第 1 层：决策循环精讲（新架构版）

> 目标：彻底理解"居民一次思考+行动"的完整旅程，知道每一环的数据格式、代码位置，
> 以及它对"狼人杀/警察卧底"玩法意味着什么。
>
> 对应文件：`game/agent/`（居民侧）+ `game/world/runtime/agent/`（世界侧 Agent 管线）
> + `game/world/integration/TownWorldAgentGateway.gd`（泵驱动）
>
> **架构变化**：旧版这一层散在 `TownWorldRuntime.gd`（2.3万行巨石）与 `AgentContract.gd` 单文件；
> 官方 #109 拆分后，World 侧决策管线在 `runtime/agent/` 13 个模块，Agent 侧合同在
> `agent/contract/` 11 个分域文件。本文所有代码位置均为新架构真实路径。

---

## 总览：7 个环节

```
世界唤醒 → 提示词编译 → LLM 决策 → 合同校验 → 世界执行 → 结果落定 → 记忆沉淀
   wake       compile       model      validate     execute     result     remember
  (World    (Agent        (Provider   (Agent      (World      (World      (Agent
   runtime   prompt)       side)       contract)   runtime)    runtime)    memory)
   agent/)
```

- 这个循环每分钟对每个活跃居民跑一次，由 `TownWorldAgentGateway` 泵驱动
  （`world/integration/TownWorldAgentGateway.gd`，并发上限 `MAX_CONCURRENT_MODEL_REQUESTS=3`，
  派发速率 `DISPATCH_RATE_PER_SECOND=0.65`，节流 0.5/s、`RATE_LIMIT_THROTTLE_DURATION_MS=30000`）
- 世界侧与 Agent 侧是完全解耦的两个世界：**世界不知道 LLM 怎么想的，Agent 不知道世界怎么算的**，
  中间只通过 wake_packet（进）和 decision（出）交换数据
- **这是理解整个项目最重要的一件事**：你改 Agent 侧（人格/提示词），世界不会自动配合；
  你改世界侧（机制），居民不一定按你的预期行动

## 环节 1：世界唤醒 wake（World 侧）

**代码**（新架构）：
- 分帧准备：`world/runtime/TownAgentWakePreparationRuntime.gd`（根目录，逐帧准备队列，避免一帧打满）
- 唤醒状态：`world/runtime/TownAgentWakeStateRuntime.gd`（谁该醒、wakeDispatchQueued 标记）
- 上下文组装：`runtime/agent/TownAgentWakeContextRuntime.gd` 的 `wake_packet()`（L31）
- 包结构：`runtime/agent/TownAgentWakePacketProjection.gd` 的 `packet()`（L39）
- 派发：`runtime/agent/TownAgentDecisionDispatchRuntime.gd`（待决定请求筛选+按居民刷新+重新派发）

世界把"该醒的居民"打包成 wake_packet：

```jsonc
{
  "decision_id": "林岚-104",           // 本轮唯一编号，必须原样返回
  "snapshot": {                        // 此刻能感知的一切
    "me": {...},                       // 自身：位置/身体状态/当前动作/金钱声望
    "place": {                         // 当前地点
      "name": "中心广场",
      "destinations": [...],           // ★可前往地点白名单
      "props": [...],                  // ★可操作道具白名单
      "activities": [...],             // ★可做活动白名单
      "service_control": {...}         // 营业开关（如果有）
    },
    "nearby": [...],                   // ★可搭话居民白名单
    "conversation": {...},             // 进行中的对话（如果有）
    "weather": "晴天",
    "social_matters": [...]            // 本人知道的公共事项（公告/委托/岗位空缺）
  },
  "conflicts": [...],                  // 冲突快照（新架构把冲突挂包顶，见第4层）
  "events": [...],                     // 上次决策后新发生的事件（按顺序）
  "action_results": [...],             // 世界确认的动作结果
  "social_response_results": [...]     // 社会回应的 World 回执
}
```

**关键点**：
- 三个白名单（destinations / nearby / props + activities）是"封闭世界"的基石——LLM 只能从
  白名单里选，从机制上杜绝编造
- 世界在这里只给"事实"，不给"指令"。模型看到的一切都是数据，规则永远在 system 里
- **对狼人杀玩法的意义**：警察的"查验/制服"、卧底的"暗杀/嫁祸"、医生的"守诊"必须出现在
  白名单（动作/活动/道具）里，否则 LLM 想做也做不了。技能入口由 `TownRoleSkillRuntime`
  （`world/runtime/TownRoleSkillRuntime.gd`）在唤醒阶段注入选项

## 环节 2：提示词编译 compile（Agent 侧）

**代码**：`agent/prompt/AgentPromptCompiler.gd` 的 `compile()`（L216）+ `_build_dynamic_context()`（L252）
+ `_render_snapshot()`（L502，wake 包→文本）

产出两条消息（OpenAI 兼容格式）：

```jsonc
{
  "messages": [
    {"role": "system", "content": "...# 居民决策基线\n<rules>...\n<background>...\n<resident_initialization>..."},
    {"role": "user", "content": "<oc_priority>...</oc_priority>\n# 本轮决定上下文\n<wake_context>...</wake_context>\n<retry_correction>...</retry_correction>\n<memory_context>...</memory_context>\n<action_constraints>...</action_constraints>"}
  ]
}
```

**system（静态）**：居民初始化时生成一次，之后每回合原样复用。含：
- 规则 6 篇：`prompts/rules/10_identity_and_knowledge.md` / `20_behavior_and_expression.md` /
  `30_data_authority.md` / `35_events_and_results.md` / `40_decision_contract.md` / `50_decision_examples.md`
- 小镇背景：`prompts/background/10_town_common_knowledge.md`
- 角色人设：`prompts/roles/<居民>.md`（8 个具名居民 + police.md + undercover.md）
- 开局 OC 分析：`agent/soul/AgentSoulProfile.gd` 的结论经 `_render_soul_profile()`（L468）注入
  —— 身份倾向影响行为，关系只作"未确认线索"

**user（动态）**：每回合现编译。`_build_dynamic_context` 从 wake_packet 推导本轮"合法动作菜单"：
- 如果本轮**必须答话** → 只给"答话"一个动作
- 如果**受伤必须反应** → 只给反应选项
- 否则 → 去 / 待着 / 托人传话 / 用道具 / 做活动 / 调整营业 / 答话(可选) / 搭话 / 冲突动作

**对狼人杀玩法的意义**：按身份给不同的**动作菜单**。卧底多"暗杀/嫁祸"、警察多"查验/制服"、
医生多"守诊"——但动作本身必须在环节 5（世界执行）有对应实现，否则就是画饼。

## 环节 3：LLM 决策 model（Provider 侧）

**代码**：`agent/model/OpenAICompatibleModelProvider.gd`（兼容网关，可配 302-ai / DeepSeek 等），
其它 13 个 Provider 在同目录（DeepSeek/VolcengineArk/Kimi/MiniMax/ZhipuGLM/AlibabaBailian/XiaomiMiMo/
OllamaCloud/GenericOpenAICompatible/ThreeZeroTwoAI + ModelProvider 基类/Catalog）

```jsonc
POST {endpoint}
{
  "model": "deepseek-v4-flash",
  "messages": [...],          // 环节2的产物
  "max_tokens": 1024,
  "stream": false,
  "thinking": {"type": "disabled"},
  "response_format": {"type": "json_object"}
}
```

返回解析做了容错：
- 容忍 markdown 代码围栏、外层文字、尾逗号 → 提取 JSON
- 截断（finish_reason=length）→ 判失败重试（`MAX_DECISION_ATTEMPTS=2`）
- **2026-08-26 修的坑**：`finish_reason` 必须做类型防御（L529-539），302-ai 网关曾返回
  custom 对象导致 `String` 构造失败 → 回调永不触发 → 全泵饿死（详见 PROJECT_GUIDE §9）

**对狼人杀玩法的意义**：这一环是"自由意志"所在。LLM 结合人设+记忆+当前处境决定动不动。
**你无法保证它一定杀人/一定投票**——戏剧性来自"它可能动手，也可能不动"。

## 环节 4：合同校验 validate（Agent 侧）

**代码**（新架构拆成 11 个分域文件）：`agent/contract/`：
- `AgentContractAction.gd` —— 动作字段白名单（`ACTION_FIELDS` 各动作必填字段精确枚举）
- `AgentContractConversation.gd` / `AgentContractEnvironment.gd` / `AgentContractEvents.gd` /
  `AgentContractIdentity.gd` / `AgentContractMedical.gd` / `AgentContractSocial.gd` /
  `AgentContractWake.gd` / `AgentContractWorkTasks.gd` / `AgentContractWorldFacts.gd` /
  `AgentContractSnapshot.gd`
- 顶层 `agent/AgentContract.gd` 仍是调度入口；`agent/conflict/AgentConflictContract.gd` 管冲突动作

检查项（核心不变）：
- `decision_id` 必须与 wake_packet 一致
- `handling` 只能 `continue_current` / `replace_current`
- 动作字段必须匹配该类型动作的 `ACTION_FIELDS`
- 搭话目标必须在 nearby、地点必须在白名单、道具必须存在、对话 id 必须匹配……

**失败处理**：`AgentDecisionAcceptancePolicy`（`runtime/agent/`）判拒绝 → 生成 `retry_correction`
（"上一次输出没有通过合同检查，保留原本意图只修正问题…"）→ 回炉重试，最多 2 次。
两次都失败 → 该轮无动作（居民保持现状）。

**对狼人杀玩法的意义**：加"查验/暗杀/守诊"等新动作，**必须同步改 `agent/contract/AgentContractAction.gd`
的 ACTION_FIELDS**，否则 LLM 每次提交都会被拦——旧版踩过警察"制服"别名坑（kill 别名）。

## 环节 5-6：世界执行 + 结果落定 execute/result（World 侧）

**代码**（新架构）：
- 请求消费：`agent/TownAgentDecisionSubmissionRuntime.gd`（决定信封入口校验、形状校验、
  社会回应消费、动作类型分派）+ `TownAgentDecisionActionRuntime.gd`（继续/替换/回滚）
- 激活：`action/TownConfirmedActionActivationRuntime.gd`（预览确认后的真正激活事务）
- 结算：`action/TownActionSettlementRuntime.gd`（完成/中断）+ `activity/TownActivityActionSettlementRuntime.gd`
- 结果结构契约：`world/contract/TownWorldResultShapes.gd`
- 事件投递：`event/TownWorldEventDeliveryRuntime.gd`（广播+按居民入队+队列写入）
- 动作结果入队：`action/TownActionResultRuntime.gd`

决策通过校验后回到世界：
- 世界按动作类型分派执行器：移动（`movement/TownGoActionAdvancementRuntime`）、活动
  （`activity/TownActivityStepExecutionRuntime`）、工作（`work/` 域）、对话（`conversation/`）、
  冲突（`conflict/TownConflictRuntime`）……
- 执行后生成**动作结果**，只有 4 种状态：

```jsonc
{"action_id": "a-1", "status": "completed", "reason": "林岚到达了工作坊"}
{"action_id": "a-2", "status": "rejected", "reason": "唐小满已经离开"}
{"action_id": "a-3", "status": "interrupted", "reason": "天气变化中断"}
{"action_id": "a-4", "status": "replaced", "reason": "被新动作取代"}
```

- 结果会作为事件广播给相关居民（`TownWorldEventDeliveryRuntime`），成为下一轮 wake 的输入，
  并进入记忆系统（环节 7）

**对狼人杀玩法的意义**：**任何新玩法的"裁决"都在这一环**：
- 卧底"暗杀"：`TownWerewolfRuntime` 判定是否夜间可用（`undercover_kill_available`）→
  夜间死亡不即时公告（`defer_night_death_announcement`）→ 天亮 `flush_pending_death_announcements`
- 投票：`TownWerewolfRuntime.start_vote_round`（08:00 起）+ LLM 经决策附件 `exile_vote` 投票 +
  12:30 `VOTE_SETTLE_MINUTE=750` 开票放逐
- 技能：`TownRoleSkillRuntime` 的 `NIGHT_SKILLS`（守诊/查验/嫁祸，晚上互不干扰）

## 环节 7：记忆沉淀 remember（Agent 侧）

**代码**：`agent/memory/ResidentMemorySystem.gd`（总入口）+ 13 个子模块：
- 证据队列：`ResidentEvidenceQueue.gd`（把动作结果转成"证据"，写盘队列防卡顿）
- 记忆整理：`MemoryOrganizer.gd`（必要时一次 LLM 调用，prompt=`prompts/memory/10_memory_organizer.md`）
- 存储：`ResidentMemoryStore.gd`（每人一份私有文件 `user://agent_runtime_memory/<居民>/`）+
  `ResidentMemoryEntryStore.gd`（条目级存储）
- 干预：`ResidentMemoryInterventionService.gd` / `ResidentMemoryInterventionStore.gd`（外部改记忆）
- 老化：`ResidentMemoryAgingService.gd`（旧记忆淡出）
- 形式记忆：`ResidentFormalMemoryBuilder.gd`（结构化经历/关系/目标投影，`FORMAL_RECALL_MAX_ITEMS=6`）
- 重评估：`ResidentMemoryReappraiser.gd` / 检索匹配：`ResidentMemoryEvidenceMatcher.gd` /
  摘要：`ResidentMemorySummaryProjector.gd` / 连续性守卫：`MemoryContinuityGuard.gd`

**关键**：记忆是"每人一份私有文件"，居民互相看不到——只有公开资料（名字/职业/家底/声望）共享。

**对狼人杀玩法的意义（最重要的一环）**：
- 卧底的"身份隐藏" = 任务记忆只有自己知道（`soul/AgentSoulProfile` 只影响倾向，不公开身份）
- 警察的"线索积累" = 记忆里的怀疑对象列表（`_police_intel_context` 会把警察情报注入 wake）
- **全部张力都在"谁知道什么、谁不知道什么"**——记忆系统天然提供
- 关系作为"未确认线索"：`runtime/relationship/TownTravelerRelationshipRuntime.gd` 记录
  对话/互动 → 亲密度（`AGENT_AFFINITY_DELTA_MIN/MAX=±5`、攻击 -10），须经真实事件才成世界事实

## 第 1 层小结 + 代码地图（新架构）

| 环节 | 文件（新架构） | 关键函数 | 狼人杀挂载点 |
|---|---|---|---|
| wake | `runtime/agent/TownAgentWakeContextRuntime.gd` + `TownAgentWakePacketProjection.gd` | `wake_packet` L31 / `packet` L39 | 注入技能选项/警察情报 |
| 派发 | `runtime/agent/TownAgentDecisionDispatchRuntime.gd` | 待决定筛选/刷新 | 投票提醒强制唤醒 |
| compile | `agent/prompt/AgentPromptCompiler.gd` | `compile` L216 / `_build_dynamic_context` L252 | 按身份给动作菜单 |
| model | `agent/model/OpenAICompatibleModelProvider.gd` | `request_decision` | （黑盒） |
| validate | `agent/contract/AgentContractAction.gd` 等 11 件 | `ACTION_FIELDS` | 新动作同步合同 |
| execute | `runtime/agent/TownAgentDecisionSubmissionRuntime.gd` + 各领域 | submit/激活/结算 | 暗杀/投票/技能裁决 |
| result | `world/contract/TownWorldResultShapes.gd` + `TownActionResultRuntime.gd` | 结果 4 态 | 结果写进记忆才有后续 |
| remember | `agent/memory/ResidentMemorySystem.gd` + 13 件 | 证据→整理→检索 | 怀疑/线索/身份隐藏载体 |

**核心心法**：
1. 世界给事实 + 白名单（wake），Agent 给意愿（LLM），世界给裁决（execute），记忆给延续（remember）
2. 想加玩法，按"白名单 → 动作菜单 → 合同 → 执行器 → 结果 → 记忆"全链路改，只改任何一环都会断
3. 观察型玩法 = 尊重 LLM 自由意志，把戏剧性建立在"记忆不对称 + 结果不可控"上
