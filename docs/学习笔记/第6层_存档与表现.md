# 第 6 层：存档与表现精讲（新架构版）

> 目标：理解世界状态怎么存/怎么恢复（存档链）、表现层怎么投影世界状态给 UI，
> 以及狼人杀状态（投票/技能/死讯延迟）在这些层里的位置。
>
> 对应文件（新架构）：
> - 持久化域：`game/world/runtime/persistence/`（14 个模块）
> - 表现投影：`game/world/runtime/presentation/`（10 个模块）+ `game/world/presentation/`（54 个文件）
> - Agent 存档：`game/agent/lifecycle/`（AgentSaveStore/AgentSessionEpoch/ResidentStateCodec）
>
> **架构变化**：旧版存档散在巨石与白名单校验；新版拆成"候选收集→快照投影→编码→提交→
> 恢复候选→分域恢复→提交"的显式管线，按域分文件（Layout/People/Work/SocialState/Animals/State）。

---

## 1. 持久化管线（persistence/ 14 模块）

**存档方向（save）**：
```
TownWorldSaveCandidateRuntime（收集各域候选）
  → TownWorldSaveSnapshotProjection（投影出只读快照）
  → TownWorldSaveCodec（schema 编解码：town-world-save vN）
  → TownWorldSaveCommandRuntime（提交写入：文件/原子性）
  → TownWorldPersistencePreparation（写盘前准备）
```

**读档方向（restore）**：
```
TownWorldRestoreCandidateRuntime（读候选）
  → TownWorldSaveCodec（解码校验）
  → 分域恢复：TownWorldRestoreState / RestorePeople / RestoreWork / RestoreLayout /
     RestoreSocialState / RestoreAnimals（各自恢复自己的状态所有权）
  → TownWorldRestoreCommitProjection（恢复投影校验）
  → TownWorldRestoreCommitRuntime（提交：替换运行时状态 + 世界版本一致）
```

**关键机制**：
- **Schema 版本**：`TownWorldSaveCodec.SCHEMA="town-world-save"`、`SCHEMA_VERSION=TownSaveSchemaRegistry.WORLD_SCHEMA_VERSION`、
  `SUPPORTED_SCHEMA_VERSIONS` 支持多版本回退（旧档可读）
- **类型标签**：`TYPE_TAG="__townWorldType"` + `VECTOR2_TAG`——字典里存类型标记，
  恢复时还原 Vector2 等结构化类型；`MAX_SAFE_INTEGER=9007199254740991` 防精度溢出
- **状态域白名单**：`STATE_KEYS` / `OPTIONAL_STATE_KEYS`——只存声明过的顶层状态，
  未知键不存不读（防止脏状态进存档）
- **私有访问禁止**：分域恢复模块各自持有自己的状态所有权（如 `TownWorldRestoreWork` 只碰工作域），
  不符合"跨模块私有访问只减不增"基线

**Agent 侧存档**（`game/agent/lifecycle/`）：`AgentSaveStore.gd`（Agent 会话存档事务）、
`AgentSessionEpoch.gd`（会话纪元）、`ResidentStateCodec.gd`（居民状态编解码）——与记忆文件分开，
居民运行的 Agent 状态（会话/模型绑点）随世界存档一起提交。

## 2. 表现层（runtime/presentation 10 模块 + world/presentation 54 文件）

**运行表现投影**（`runtime/presentation/`）：
| 模块 | 职责 |
|---|---|
| `TownResidentStateProjection.gd` | 居民状态投影（给 UI 的只读快照） |
| `TownResidentPublicQueryRuntime.gd` | 居民公开查询（名字/职业/声望等共享数据） |
| `TownResidentMovementProjection.gd` | 移动位置投影（地图上的人在哪） |
| `TownActionPresentationSemantics.gd` | 动作文案语义（default_doing 等 UI 文案） |
| `TownPlacePresentationQuery.gd` / `TownWorldActorPresentationState.gd` | 地点/演员表现状态 |
| `TownResidentProfileEditor.gd` / `TownResidentProfileCommandRuntime.gd` | 居民资料编辑/命令 |
| `TownWorldFrameBudgetRuntime.gd` | ★帧预算：表现刷新分帧（`RESIDENT_PRESENTATION_REFRESH_BUDGET_PER_ADVANCE=3`、
| | 地点变更信号每轮 1 条、感知最多延迟 12 轮），防表现开销卡帧 |
| `TownWorldTelemetryRuntime.gd` | 遥测/性能探针 |

**图层表现**（`world/presentation/` 54 文件，10 个方向）：
`animals/`（动物表现）、`announcement/`（公告 UI）、`conflict/`（冲突表现投影）、
`environment/`（天气/环境 UI）、`game_flow/`（游戏流程：开场/结算）、`lifecycle/`（出生/死亡表现）、
`residents/`（居民卡/气泡/细节页投影）、`session/`（会话页），`town_runtime/`（小镇运行表现）、`ui/`（通用 UI）
——**UI 只读投影，不碰 runtime 状态**；表现层与运行时之间靠 `TownWorldFrameBudgetRuntime` 分帧同步。

## 3. 存档链对狼人杀改造的意义

1. **狼人杀状态要进存档**（不能只活在内存）：
   - 投票轮次/已投票人/死讯延迟队列（`TownWerewolfRuntime` 的 state）
   - 技能次数（医生守诊/查验/嫁祸剩余额度）
   - 警察设备状态、暗杀额度
   - 部署原则：归 `TownWerewolfRuntime.default_state()` 初始化，走 `STATE_KEYS` 白名单
2. **读档兼容**：`SUPPORTED_SCHEMA_VERSIONS` 多版本回退 = 老存档（无狼人杀域）打开时
   自动补 `default_state()`，不炸档
3. **死讯延迟的表现**：夜间死亡不即时公告 → 天亮 `flush_pending_death_announcements` 一次性公布，
   表现层公告域（`presentation/announcement/`）消费
4. **移动与表现分帧**：狼人杀全城大会投票（多人同时决策）时，`TownWorldFrameBudgetRuntime`
   保证表现刷新不卡帧——决策管线优先，表现排队

## 4. 存档测试与排查

- 回归：`tests/town_world_save_test.gd`（181 项）+ `session_save_continue_roundtrip_test.gd`、
  `game_flow_daily_auto_save_test.gd`、`game_flow_host_formal_entry_test.gd`
- 存档位置：`%APPDATA%\Godot\app_userdata\我的ai小镇\`
- **stale/存档链问题排查**：`docs/存档迁移手册.md` 记录了 opening 归一化、路线重放放宽、
  初始化等价比较剥离 money/reputation 等历史修复
- **改存档结构** = 改 `TownWorldSaveCodec` 的 `STATE_KEYS` + 版本号 + 各分域恢复模块，
  **必须向后兼容**（旧档可读）——这是拆分基线停止条件之一
