## 三、审讯会核心机制（最终状态）

### 3.1 流程（08:00 触发，替代旧 11:00 镇民大会）

```
08:00 开会 → 世界冻结 → 汇报期 → 审讯期 → 投票期 → 开票公布 → 解冻
          (120s 收齐/超时) (警察≤5人/600s兜底) (90s 收齐/超时立即开票)
```

- **冻结**：`assembly_frozen` 独立标志（非 is_paused）短路 `TownWorldAdvanceRuntime.advance`
  （分钟不推进）；LLM 决策派发与对话**仍放行**（设计）
- **请求消耗**：汇报期=存活居民×1；审讯期=仅警察+被审者×轮数；投票期=存活居民×1
- **阶段切换源**：真实秒驱动超时（tick_assembly，advance 入口短路前每帧调用）+ 收齐优先
- **存档**：assembly 状态挂 `world._werewolf_state`（TownWorldRuntime.gd:716），随存档 werewolfState 域持久化

### 3.2 三层动作约束（模型该做什么/能做什么）

| 层 | 作用 | 位置 |
|---|---|---|
| prompt 阶段提示 | 教模型当前阶段+参数填法（kinds/汇总/逐字稿） | AgentPromptCompiler `_render_snapshot` assembly 块 |
| 动作裁剪 | 只给该阶段允许的动作选项 | AgentPromptCompiler 约束组装（report 只汇报/vote 只投票） |
| 白名单拦截 | 兜底拒绝非法动作 | TownActionPreparationRuntime.prepare 入口 `assembly_action_allowed` |

### 3.3 阶段白名单

- **汇报期**：非警察只能「向警察汇报」（kind∈目击/听到/怀疑/不汇报）；警察等待
- **审讯期**：警察=搭话/答话/结束审讯；平民=答话（被审中）/待着
- **投票期**：全员只能「投票放逐」

### 3.4 参与者过滤（请求风暴治理）

`assembly_participant`：汇报期=未汇报非警察；审讯期=警察+有活跃对话者；
投票期=未投票者。非参与者请求在 take() 直接丢弃（wakeDispatchQueued=false），
避免冻结期间全员持续决策烧请求（实测审讯期每人烧多个"待着"请求）。

### 3.5 双通道提交

即时动作（submit_valid 分支「向警察汇报/结束审讯/投票放逐/使用技能」）+ 决策附件
（report/exile_vote/night_skill）双通道兼容——模型输出哪种都接受。

### 4.2 完整复盘修复（bdc7946，用户问"会不会还有 bug"后系统审查发现）

| 问题 | 严重度 | 修复 |
|---|---|---|
| **警察无法远程审讯**：搭话目标只从 nearby 注入，08:00 开会时警察身边通常 1-3 人，想审的嫌疑人不在附近就没有选项也没有 ID；身边无人时审讯期整段卡到 600s 兜底 | 🔴 高 | prompt 搭话 targets 合并 `interrogationTargets`（远程提审） |
| **汇报期警察 wake 误导**：8 点天亮唤醒全员含警察，prompt 叫警察"向警察汇报"必被白名单拒 | 🟡 中 | 警察快照 role=police + "汇报正在收集中，警察请等待" |
| **双通道同时提交被拒**：模型同时输出「向警察汇报」动作+report 附件，附件先成功、动作再报"已提交"→ 整个决策打回，重试再报"已提交"，汇报成功但模型永远看不到反馈 | 🟡 中 | 记录附件提交结果（attachmentSubmitted），同类型重复动作视为幂等成功；无动作但附件已生效视为有效 |
| **投票期被审者被对话锁死**：审讯对话残留（waitingFor=被审者）→ wake_requires_reply 只给「答话」，投票白名单只允许「投票放逐」→ 反复被拒烧请求到超时弃权 | 🟡 中 | `_begin_vote` 结束警察参与的活跃对话 + wake_requires_reply 分支合并 exile_vote/night_skill 附件兜底 |
| 投自己没被拦（快照排除但提交不校验） | 🟢 低 | submit_vote 加"不能投自己" |
| 汇报期居民盯着"可前往地点"想出门（与白名单矛盾） | 🟢 低 | 大会期间渲染"时间冻结，无法前往" |

### 4.3 冻结-解冻不变量（35e130d，抽象模型）

**原理**：wake 快照每次从零拼装（finalize），大会期间只是"叠一层"（assembly 键 +
constrain_wake 裁剪），叠加的存在条件 = `assembly.phase != "idle"`。解冻 = phase 变
idle = 叠加层自动消失，底层数据从未被污染。

| 类别 | 暂停期间改动 | 恢复机制 |
|---|---|---|
| 瞬时叠加（自动消失） | assembly 提示/逐字稿注入、constrain_wake 裁剪、搭话 targets 合并、take 过滤、prompt 裁剪、附件合并 | 每次 wake 从零拼装 + 条件 phase!=idle |
| 有意持久（设计如此） | 汇报数据、逐字稿、审讯登记、开票/放逐/死亡、结束审讯对话、公告 | 保留在 state，idle 后不读取 |
| 挂起-恢复（对话引擎） | 被审者动作挂起（hold）、对话邀请 | _end_conversation → _resume_action_after_conversation |

**三条底层保证**：①无共享可变状态（finalize 深拷贝+整体赋值）；②被过滤请求不丢
（只清 wakeDispatchQueued，_begin_vote 的 _assembly_wake_all 重新覆盖全员）；
③平票/流会出口不卡人（投票是即时动作不覆盖 currentAction，生活靠动作+生活节奏继续）。

已固化为测试断言（diag_assembly 131→141 checks）：解冻后搭话目标恢复纯 nearby、
生活选项回来、wake 无大会残留、exile_vote 空、流会出口同样验证。

### 4.4 读档页崩溃（6f92ee0）——重启后第一次进读档页才炸

**现象**：`ERROR: 加载游戏页 slot state 无效：read_only`，读档页整体打不开。

**根因链**：
```
狼人杀化改造(34c2222)给 world state 加 werewolfState 域 → state 键数 27→28
→ 兼容账本 RELEASES 仍登记 beta6=27 分区，检测要求【严格相等】
  (TownSaveCompatibilityRegistry.gd:375)
→ 28 键档不匹配任何已知 release → unknown_combination
→ 启动目录判「只读」(read_only)
→ StartupLoadGameScreen VALID_SLOT_STATES 白名单没有 read_only → 整页 push_error
```
**为什么之前能玩**：同一局内 continue 走 session 恢复链（容忍度高），重启后进读档页
走启动目录完整兼容性检测 → 炸。**bug 从 8-16 狼人杀化就埋下，第 8 天第一次重启才暴露**。

**修复**（3 层）：
1. RELEASES 登记 `beta7`（worldSectionCount=28 + 本地警察职业指纹 bf242f42）作为当前发行版；官方 beta6（27 键）不受影响
2. `detect_release` 允许「存档记录的 release 是候选的前序」——旧档（recorded=beta6 但 28 键）按 beta7 识别，无需迁移
3. UI 白名单加 read_only（未来版本档不再崩页面，按"只读存档"禁用态）

**顺手修掉的测试腐坏**（迁移遗留，与本次无关）：
- `town_save_compatibility_registry_test` 硬编码旧活动指纹 `70dcd5`（官方改活动数据后账本已用 `bc3442e1`）→ 该测试 34c2222 后一直红，换常量后 67 checks 全绿

### 4.5 全员决策 REJECTED（51c1069）——两类错误叠加

**现象**（godot-20260829-012843.log）：37 次 `AGENT_DECISION_REQUEST_REJECTED` 全是
`events[N].type 不是合法事件类型` + 84 次 `error_type=http | 详情=模型调用失败`。

**根因 1（REJECTED）**：世界会产生 5 个契约白名单（AgentContract.EVENT_TYPES）外的
事件类型：
| 事件类型 | 来源 | 为什么现在才炸 |
|---|---|---|
| 钟声公告 | dd43d9c 的 town_bell 投递 | 改造后第一次大量进入居民 wake——以前走「公告发布」（白名单有），方案A 后直接 enqueue「钟声公告」，漏了同步契约 |
| 正式通知送达 | postal_notice 投递 | 一直存在，恰逢触发 |
| 居民公开反应 / 外出就医 / 卧底任务完成 | 公告反应/就医/狼人杀终局 | 防御性补全 |

修复：EVENT_TYPES 补全 5 个 + `_validate_event_fields` 加公告类字段校验（钟声公告
delivery_mode / 正式通知送达 message_id）。probe 实证 5 个新类型校验 errors=[]。

**根因 2（http 详情丢失）**：真实原因被两层抹平——
1. `DecisionExecution._validate_model_decision` 把 provider 错误统一替换成「模型调用失败」
2. `TownAgentProviderService._public_diagnostic` 白名单又把 provider 存的真实 `errors` 过滤掉

修复：_public_diagnostic 公开 errors（截断 200 字符，不含请求体/凭据）；gateway 行为流
日志详情优先取 provider 原始错误——重跑后能看到「模型服务返回 HTTP xxx」/「连接超时」。

**http 错误的本质**（哪个 4xx）需修复透传后重跑确认；若是 429/5xx 属 mimo 网关侧，
若是 400/422 则查请求内容。

## 六、新增踩坑条目（补充 08-25 手册）

### 6.1 契约/事件白名单
1. **AgentContract.EVENT_TYPES 白名单漏登记**：任何新投递给居民的事件 type 必须同步
   登记，否则 wake events 校验失败 → 全员决策 REJECTED + CONTINUITY_FALLBACK
   （实证：钟声公告 dd43d9c 改投递后 37 次 REJECTED）
2. **新增事件类型字段校验**：_validate_event_fields 公告分支要同步（钟声公告
   delivery_mode、正式通知送达 message_id）；存档恢复校验（TownWorldRestorePeople）
   与契约校验的字段要求必须一致，否则恢复路径误伤
3. **双通道提交幂等**：附件（report/exile_vote/night_skill）与同类型动作同时输出时，
   附件先提交成功 → 动作分支报"已提交"会把整决策打回。consume() 记录 attachmentSubmitted，
   submit_valid 同类型重复视为成功；无动作但附件已生效视为有效

### 6.2 存档兼容账本
4. **world state 加域必须登记新 release**：worldSectionCount 严格相等匹配，加域不改
   版本号 → 存档判 unknown_combination → 目录 read_only → 读档页打不开
   （实证：werewolfState 域 27→28，登记 beta7 解决）
5. **recorded release 前序放行**：旧 release 时代保存的新结构档（recorded=beta6 但
   28 键）需要在 detect_release 放行升级场景，否则"recorded release conflicts with
   save evidence"
6. **测试硬编码指纹腐坏**：SCHEMA_REGISTRY 常量更新后（官方改活动数据）测试字面量
   必须同步，否则兼容测试静默红（70dcd5→bc3442e1 实证）

### 6.3 诊断可观测性
7. **provider 错误被两层抹平**：DecisionExecution 统一替换 + _public_diagnostic 白名单
   过滤 → 行为流日志只剩"模型调用失败"。新增诊断字段必须显式加进 _public_diagnostic
8. **gateway 日志详情优先级**：先取 diagnostic.errors（provider 原始错误，含 HTTP 状态/
   网络/解析原因），再回退 agent_errors

### 6.4 工具坑
9. **PowerShell -replace 对中文内容文件不可靠**（编码转换丢替换）→ 改文件内容用
   edit 工具，不要用 Get-Content/Set-Content 管道改中文
