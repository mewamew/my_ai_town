# 手机端适配设计

## 目标与边界

手机版与桌面版共享同一套世界模拟、存档、居民 Agent、场景数据和美术资源，但输入方式、窗口安全区、操作尺寸和部分页面排版分别处理。共享代码不等于把桌面界面强行拉伸到手机，也不等于复制一份会长期分叉的完整游戏。

移动端改动必须遵守以下边界：

- 桌面运行时保持现有鼠标、键盘、悬停、滚轮和窗口行为。
- 只有 Android 或 iOS 运行时才挂载移动输入服务。
- 平台差异优先放在独立适配层；世界规则和业务数据继续共用。
- 前景面板、文字和图标按同一比例变化，不允许只放大文字或只拉宽图片。
- 额外屏幕空间由背景、留白或更多可滚动内容承担，不用非等比拉伸填满。
- 所有移动端页面必须考虑圆角、挖孔、系统手势区和平板或折叠屏展开后的比例变化。

## 代码组织

仓库保持一个 Godot 工程。公共目录继续承载桌面和手机都使用的功能；移动端基础能力集中在 `ui/mobile`，页面只在确有差异时调用适配能力。

移动端基础层负责：

- 判断当前是否为 Android 或 iOS；不能根据桌面窗口尺寸猜测平台。
- 计算安全区域、居中前景区域、背景铺满比例和屏幕宽度分类。
- 把触屏按下、抬起和拖动统一映射为页面可理解的指针事件。
- 为可滚动控件提供全局手指拖动，并防止拖动结束后误点列表项。
- 管理手机输入框的短按、长按和拖动区别，按需调用系统输入法。

移动端页面适配按功能拆分成后续独立提交，不与平台基础混在同一个 PR：

1. 移动与场景交互：摇杆、右侧动作区、建筑入口、动物和居民命中。
2. 小镇 HUD：左右工具栏、速度栏、时间天气、化身框和安全区。
3. 目录与详情页：居民、地点、日志、关系、记忆等列表与滚动。
4. 启动、设置和存档：主菜单、模型输入、加载遮罩与 Android 存档恢复。
5. 性能与发行：真机帧时间、内存、触摸延迟和 Android 打包流程。

## 屏幕与布局规则

手机以横屏游玩为主，同时覆盖常见的 4:3、3:2、16:10、16:9 和 21:9 横屏。布局不绑定某个具体机型分辨率，而按当前可用区域计算。

### 前景页面

完整页面沿用设计参考尺寸并整体等比缩放，保持内容完整可见。屏幕比页面更宽时，页面居中，两侧使用背景或留白；屏幕更窄时，按短边等比缩小。页面内部若内容超过可用高度，使用可触摸滚动，不压缩行高或让文字越过底框。

### 游戏画面

地图和场景保持等比例，不拉伸角色、建筑或图标。超宽屏可以适度显示更多横向场景，或让背景等比覆盖后裁切短边。固定 HUD 根据安全区域贴边，图标自身保持比例，只有允许伸缩的木框或纸张中段可以延展。

### 触控尺寸

主要操作区域至少为 48 个逻辑像素。可见图片可以略小，但命中区域必须覆盖完整按钮并留出间距。动态操作按钮只有在当前存在相应目标时显示，不保留桌面键位提示。

## 输入与滚动

桌面鼠标逻辑继续保留；手机以触屏事件为准。触屏按下不能立即等同于点击，必须等待抬手或拖动判断：

- 位移未超过阈值且很快抬手：普通点按。
- 位移超过阈值：滚动或场景手势，不能再触发点击。
- 按住达到时长：长按，由输入框或后续页面自己的长按操作处理。

所有 `ScrollContainer`、长文本、日志和多行输入区域都必须支持手指直接拖动。拖动过程更新控件原有滑条，使视觉位置和数据位置一致；拖动后的抬手需要被消费，避免顺带打开下面的居民、地点或日志条目。

## 手机文本输入

进入含输入框的页面时不自动打开键盘。只有完成一次短按输入框后才调用系统输入法，键盘使用玩家手机当前配置的底部或悬浮形态。

长按输入框时调用 Android 系统文本操作栏，提供系统剪贴板能力；游戏不绘制一套仿系统的复制粘贴菜单。拖动输入框时不弹键盘，也不触发粘贴操作。桌面输入框继续使用 Godot 原有上下文菜单和快捷键。

## 桌面版隔离检查

每个移动端 PR 至少验证以下内容：

- macOS、Windows 或 Linux 运行时不会挂载移动输入服务。
- 桌面小窗口不会因为尺寸接近手机而切换到触控模式。
- 桌面鼠标左键、键盘、滚轮和输入框上下文菜单保持原逻辑。
- Android 专用项目设置使用 Godot 平台覆盖项，不改桌面参考分辨率和窗口限制。
- 共用脚本中的移动分支都以真实平台判断开始，不能用宽高比替代平台判断。

## 提交与验收顺序

每一批改动从最新 `main` 建立干净分支，只迁移已经明确归属该批的文件。先完成自动检查和桌面隔离检查，再生成 Android 包交给真机验收。真机验收通过后再合入主分支；失败时只修当前批次，避免把尚未验证的整个手机工作区一起带入。
